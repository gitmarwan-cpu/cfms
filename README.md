# CFMS — نظام إدارة الشكاوى والمقترحات

مشروع جديد تم إنشاؤه بالكامل من الصفر بناءً على طلب العميل، بالتقنية:
**Node.js/Express (API) + PostgreSQL + React (SPA مبنية ضمن نفس الـ repo)**.

## البنية

```
cfms/
  backend/     # Express API + Sequelize (PostgreSQL) + Auth (JWT)
  frontend/    # React (Vite) - نموذج تقديم شكوى/مقترح بواجهة عربية RTL
```

## التشغيل - Backend

```bash
cd backend
cp .env.example .env      # عدّل بيانات الاتصال بقاعدة البيانات و JWT_SECRET
npm install
npm run migrate           # إنشاء الجداول
npm run seed               # استيراد 22 محافظة و335 مديرية + مستخدم admin افتراضي
npm run dev                 # تشغيل الخادم على المنفذ 4000
```

بيانات دخول المستخدم الافتراضي بعد الـ seed (يجب تغييرها فوراً):
- البريد: `admin@cfms.local`
- كلمة المرور: `ChangeMe#12345`

### تشغيل الاختبارات

```bash
npm test
```

الاختبارات تستخدم SQLite في الذاكرة (بدون الحاجة لقاعدة بيانات PostgreSQL فعلية) لتبقى سريعة ومعزولة.

> ⚠️ **ملاحظة تقنية مهمة**: بيئة التنفيذ التي أنشأتُ فيها هذا المشروع لا تملك اتصالاً بالإنترنت (`npm install` فشل بخطأ 403/شبكة معطّلة)، لذا لم أتمكن من تشغيل `npm install` أو `npm test` فعلياً للتحقق التلقائي. تحققتُ بدلاً من ذلك من خلو كل ملفات الباك إند من أخطاء بناء الجملة (`node --check`) وهذا نجح على كل الملفات، لكن **لم يتم تشغيل الاختبارات فعلياً بعد** — الرجاء تشغيل `npm install && npm test` عندك للتأكد قبل النشر.

## التشغيل - Frontend

```bash
cd frontend
cp .env.example .env       # عدّل VITE_API_BASE_URL إذا لزم
npm install
npm run dev                 # يعمل على http://localhost:5173
```

## قاعدة البيانات: مصدر بيانات المحافظات/المديريات

تم استخراج البيانات من ورقة **Admin** داخل ملف `المحافظات_اليمنية_والمديريات.xlsx`
لأنها كانت أنظف أوراق الملف: 22 محافظة، 335 مديرية، بدون تكرار أو مديريات
بدون محافظة أب. الأسماء العربية أُخذت مباشرة من عمود `label` الموجود أصلاً
في الملف (لم تكن هناك حاجة لترجمة إضافية).

**ملاحظة**: باقي أوراق الملف (`ورقة1`, `Codes`, `Codes_camp`, `ورقة3`) تحتوي
بيانات مشابهة لكن بصيغ وأغراض مختلفة (بعضها خاص بمشروع حماية طفل/استجابة
إنسانية غير علاقة بـ CFMS)، ولم تُستخدم لتفادي استيراد بيانات غير ذات صلة.

## الحقول في نموذج الشكوى (مبنية على نموذج QR-ME-02-01 المرفق)

النموذج الأصلي (PDF/صورة ممسوحة ضوئياً) لم يحتوِ نصاً قابلاً للاستخراج،
فتمت قراءته بصرياً، واستُنتجت منه الحقول التالية مع إضافة حقول تُعتبر
ضرورية لأي نظام CFMS حديث (مثل: خيار عدم الكشف عن الهوية، تصنيف حساسية
الشكوى، قناة الاستلام، الموافقة على معالجة البيانات). هذه إضافات وليست
موجودة حرفياً في النموذج الورقي، ويجب مراجعتها مع الجهة المعنية.
