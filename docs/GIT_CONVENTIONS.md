# Git Tagging Conventions

> يُطبَّق هذا من الآن فصاعداً. الوسوم السابقة لهذه الاتفاقية (`phase1-3-complete`)
> تبقى كما هي دون إعادة تسمية — راجع "السياق التاريخي" أدناه.

## القاعدة

الوسوم تُمثِّل **إنجازاً معمارياً مكتملاً وقابلاً للاستخدام**، وليست ترقيماً
افتراضياً لمراحل لم تُنفَّذ بعد. **لا** تُستخدم أرقام تسلسلية مبنية على افتراض
(مثال: `before-phase1-10`) — كل رقم أو اسم في الوسم يجب أن يعكس شيئاً موجوداً
فعلاً في المستودع وقت إنشاء الوسم، ويُتحقَّق منه عبر `git tag --list` **قبل**
اختيار الاسم/الرقم التالي، وليس افتراضه.

## الصيغة

```
cfms-<milestone-slug>-v<N>
```

- `milestone-slug`: اسم وصفي بالإنجليزية، `kebab-case`، يصف **القدرة** المكتملة
  (وليس رقم مرحلة داخلي من `docs/ROADMAP.md`).
- `v<N>`: رقم صحيح يبدأ من `1`. يُزاد فقط عند إضافة حقيقية جوهرية لنفس القدرة
  لاحقاً (مثال: `cfms-workflow-foundation-v1` ← لاحقاً عند بناء طبقة التنفيذ
  الكاملة، الاسم الأنسب هو milestone جديد كلياً مثل `cfms-workflow-engine-v1`،
  وليس رفع رقم نفس الاسم، لأن "foundation" و"engine" قدرتان مختلفتان فعلياً).

## قبل إنشاء أي وسم جديد

```bash
git tag --list "cfms-*"          # تحقّق من الوسوم الموجودة فعلياً، لا تفترض
git log --oneline -1              # تأكد من الـ commit الذي سيُوسَم فعلياً
```

## خط الزمن الحالي (مثال توضيحي، وليس التزاماً مقفلاً بالترتيب)

| الوسم | يمثّل | الحالة |
|---|---|---|
| `phase1-3-complete` *(قبل هذه الاتفاقية)* | Multi-Tenant + RBAC + Tenant Isolation (commit `41aa3b4`) | ✅ موجود فعلاً |
| `cfms-workflow-foundation-v1` | طبقة قاعدة بيانات Workflow Engine (تعريفات/حالات/انتقالات، بلا تنفيذ) | 🔶 جاهز للتطبيق - راجع الـ patch المُسلَّم |
| `cfms-workflow-engine-v1` | طبقة تنفيذ Workflow كاملة (services/routes/RBAC enforcement) | ⏳ مستقبلي |
| `cfms-notification-v1` | Notification Engine (Email/SMS/WhatsApp) | ⏳ مستقبلي |
| `cfms-reporting-v1` | Reporting/Dashboard Engine | ⏳ مستقبلي |
| `cfms-erp-core-v1` | اكتمال Core Platform بالكامل (كل بنود Phase 1 في `docs/ROADMAP.md`) | ⏳ مستقبلي |
| `cfms-beta-v1` | أول نسخة قابلة للاستخدام الفعلي من قبل مؤسسة حقيقية | ⏳ مستقبلي |
| `cfms-v1.0.0` | أول إصدار إنتاجي مستقر | ⏳ مستقبلي |

هذا الجدول **توضيحي وقابل للتعديل** — لا يُلزم بترتيب زمني صارم؛ الأهم أن كل
اسم يُطلَق فقط عند اكتمال القدرة التي يصفها فعلياً، مُتحقَّقاً منه (اختبارات +
Postgres حقيقي)، وليس عند بدء العمل عليها.

## من يُنشئ الوسم ومتى

- يُقترَح الاسم عند تسليم أي patch/PR يمثّل إنجاز قدرة كاملة (وليس جزءاً منها
  كما في "Part 1" لهذه الدفعة تحديداً — لا يُوسَم جزء غير مكتمل).
- يُنشَأ الوسم **بعد** التطبيق والدفع الفعلي إلى `main` من قبل صاحب المستودع،
  وليس تلقائياً من قبل أي وكيل تنفيذ ذاتي دون مراجعة بشرية مسبقة.
